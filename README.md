# Claude Code로 개인 투자 리서치 자동화한 방법

> 매매는 내가 직접 한다. AI는 리서치·정리·계산·모니터링만 한다.

Claude Code Skills로 만든 개인 투자 리서치 보조 시스템입니다. 특정 종목·계좌 정보는 빠져 있고, **방법론과 시스템 설계**만 담았습니다.

📺 **원본 출처**: 종목 딥다이브 3종(기업 해독기·스토리 리더·가격 판독기)의 원형은 제가 만든 게 아니라 타민더마켓 유튜브 채널에서 배포한 스킬을 벤치마크한 것입니다. ("클로드 스킬을 주식 투자 자동화에 써봤는데.. 결과가 미쳤습니다") 저는 이걸 받아서 포트폴리오 연동, 매일 브리핑, 대시보드 같은 상위 레이어를 얹었습니다.

👉 실전 활용법(트리거 문구, 하루 흐름)은 [`가이드.md`](가이드.md)에 정리해뒀습니다.

---

## 1. 왜 만들었나

투자 정보를 매일 챙기는 게 힘든 이유는 두 가지였습니다.

1. **리서치는 시간이 오래 걸린다.** 10-K(사업보고서) 하나 제대로 읽으려면 몇 시간이 든다.
2. **매일 챙길 건 아닌데, 안 챙기면 놓친다.** 실적 발표, 환율 급변, 뉴스 같은 건 매일 훑어야 하지만 매일 깊게 파고들 필요는 없다.

그래서 "넓고 얕은 매일 체크"와 "좁고 깊은 온디맨드 분석"을 분리했습니다. AI가 하는 일은 철저히 리서치·정리·계산까지고, **사라/팔아라 같은 매매 판단은 하지 않습니다.** 이건 시스템 전체를 관통하는 헌법 같은 규칙입니다 (아래 3번 참고).

## 2. 전체 구조 (2층)

```
1층: 매일 (넓게, 자동/반자동)
   └─ 일일 브리핑 — 보유 종목 밤사이 움직임, 환율·매크로, 관심 테마 뉴스, 다가오는 이벤트
        │
        │  "이 종목은 지금 깊이 봐야 한다" 신호
        ▼
2층: 온디맨드 (좁고 깊게, 필요할 때만 호출)
   ├─ 기업 해독기   — 이 회사 뭐 하는 회사야?  → 한 장 요약 카드
   ├─ 스토리 리더   — 요즘 이 회사 어때?       → 지난 2~3년 공시·어닝콜 변화 추적
   └─ 가격 판독기   — 지금 사도 되나?         → 역DCF로 "이 가격이 요구하는 성장률" 역산
```

1층이 매일 훑으면서 "이 종목 실적 임박했으니 스토리 리더 돌려봐" 같은 신호를 주고, 2층은 그 신호를 받아 필요할 때만 깊게 들어가는 구조입니다. 매일 모든 종목을 10-K 수준으로 파고들 필요는 없으니까요.

포트폴리오 전체를 종합 평가하는 1.5층(콕핏)도 있습니다. 종목별 카드들을 모아 집중도·리스크·수익 기여도를 정량화합니다.

## 3. 핵심 원칙 — 모든 기능이 공유하는 안전장치

이 다섯 가지는 어떤 분석을 돌리든 예외 없이 적용됩니다. 전문은 [`.claude/skills/investing-principles.md`](.claude/skills/investing-principles.md)에 있습니다.

| 원칙 | 내용 |
| --- | --- |
| **출처 규칙** | 출처 없는 숫자는 쓰지 않는다. 모르면 "확인 필요"로 표기. 업로드 자료는 페이지까지, 웹검색은 URL만 (페이지 번호 추측 금지 — 가장 위험한 환각 지점) |
| **계산 규칙** | 모든 수치 계산은 코드 실행으로. 암산 금지. 이상치(예: FCF가 3년 평균 대비 ±40% 이상 벗어남)는 자동 감지 |
| **사실/해석 분리** | 자료에 있는 건 `[사실]`, AI 판단은 `[해석]`으로 구분 표기. 변화가 없으면 "변화 없음"이 정답 — 억지로 스토리를 만들지 않는다 |
| **매매 신호 금지** | "사라/팔아라"를 말하지 않는다. "어디를 더 파봐야 하는지"만 제시. 리밸런싱·세금도 계산과 시나리오만 보여줄 뿐 비중을 정해주지 않는다 |
| **AI는 1차 스크리너** | 오류가 0%는 아니라는 전제. 투자 판단에 직접 쓰는 숫자는 원문에서 한 번 더 확인. 후보를 빠르게 좁혀주는 도구로만 쓴다 |

## 4. 실제로 뭘 만들었나 — 6개의 "스킬"

Claude Code의 **Skills** 기능으로 각 분석 절차를 재사용 가능한 모듈로 만들었습니다. 스킬은 트리거 문구(예: "AAPL 분석해줘")를 인식하면 정해진 프로세스·출력 형식을 그대로 따라가는 일종의 "전문화된 프롬프트 + 절차서"입니다.

### 2층 — 종목 단위 딥다이브

**① [기업 해독기](.claude/skills/company-decoder/SKILL.md) (Company Decoder)**

> "이 회사 뭐 하는 회사야?"를 10분 안에 이해하게 만드는 한 장 요약 카드.

- 돈 버는 구조를 다이어그램으로 그리고, 매출을 사업부문·지역 두 축으로 쪼갠다.
- 업종별로 진짜 중요한 지표를 다르게 뽑는다 (예: 구독 서비스=이탈률, 제조업=가동률, 소매=동일점포매출).
- 티커만 주면 웹검색으로 즉시 분석, 10-K/사업보고서를 업로드하면 페이지 출처까지 명시한 정밀 분석 — 두 모드를 지원.

**② [스토리 리더](.claude/skills/story-reader/SKILL.md) (Story Reader)**

> "요즘 이 회사 어때?" — 요약 카드가 스냅샷이라면 이건 지난 2~3년의 영화.

- 연도별 공시(10-K 등)를 문장 단위로 비교해 **새로 등장한 문구, 사라진 문구, 미묘하게 약해진 표현**(`will→may`, "강력한 성장→안정적 성장" 같은 톤 다운)을 찾는다.
- 어닝콜(실적 발표 콘퍼런스콜) 분기별 경영진 자신감을 추적하고, 가이던스로 약속한 숫자와 실제 달성치를 대조한다.
- 사람이 수백 페이지짜리 문서 여러 개를 나란히 놓고 비교하는 건 사실상 불가능한데, 이걸 대신 해주는 게 핵심 가치.

**③ [가격 판독기](.claude/skills/price-decoder/SKILL.md) (Price Decoder)**

> "지금 사도 되나?" — 적정주가를 계산하지 않고, 거꾸로 묻는다.

- 일반 DCF(현금흐름할인법)는 성장률을 내가 추정해서 넣어야 하지만, 이 방법은 **역DCF**: 지금 이 주가가 성립하려면 회사가 앞으로 얼마나 벌어야 하는지를 역산한다.
- 그렇게 나온 "시장이 요구하는 성장률"을 회사의 과거 실제 성장률과 나란히 놓고 비교한다. "중고차에 5천만원이 붙어 있으면, 그 성능이 실제로 나오는 차인가?"를 묻는 것과 같은 논리.
- 할인율(WACC) 민감도 분석을 필수로 포함해서 하나의 숫자에 의존하지 않게 만든다.

### 1.5층 — 포트폴리오 종합

**④ [포트폴리오 콕핏](.claude/skills/portfolio-cockpit/SKILL.md) (Portfolio Evaluator)**

> 종목별 카드를 모아 포트폴리오 전체를 진단.

- 집중도(HHI 지수 등)와 ETF를 경유한 숨은 중복 노출(예: 개별주 + 그 종목이 많이 담긴 지수 ETF)까지 계산.
- 자산 유형별로 다르게 평가 — 개별 종목은 펀더멘털·역DCF가 가능하지만, 지수 ETF는 지수 총계로, 원자재 ETF(예: 금)는 애초에 펀더멘털이 없다는 걸 명시하고 다른 잣대(실질금리·달러 방향)를 쓴다.
- 환율 노출도 계산 — 해외자산 비중이 높으면 원화 환산 수익률이 환율에 얼마나 민감한지 표기.

### 1층 — 매일 자동/반자동

**⑤ [일일 브리핑](.claude/skills/daily-brief/SKILL.md) (Daily Brief)**

> 이 시스템의 오케스트레이터. 오늘 뭘 봐야 하는지 한 화면으로.

- 보유 종목 밤사이 움직임, 환율·금리 같은 매크로, 관심 테마 뉴스, 다가오는 실적·이벤트를 정리.
- 가장 중요한 부분은 **"오늘의 액션 신호"** — 예: "실적 7일 이내로 임박한 종목 → 스토리 리더를 돌려봐", "밤사이 ±5% 이상 움직인 종목 → 가격 판독기로 밸류 재점검". 브리핑 자체가 결론을 내리는 게 아니라 어디를 더 파야 하는지만 짚어준다.

**⑥ [대시보드 갱신](.claude/skills/dashboard-refresh/SKILL.md) (Dashboard Refresh)**

> "갱신해줘" 한마디로 브리핑과 대시보드를 최신화.

- 매일 자동 실행이 아니라 부를 때만 도는 반자동 방식으로 결정 (별도 API 청구를 피하고 구독 한도 안에서만 쓰기 위해).
- 웹검색으로 최신 가격·환율·뉴스를 받아 브리핑 파일과 HTML 대시보드를 함께 갱신하고, 재생성 후에는 로컬 서버로 렌더링을 실측 검증(레이아웃 깨짐·가로 스크롤 등)한 뒤 발행.

## 5. 실제 사용 흐름 (예시)

실제 보유 종목 대신 예시로 설명하면:

```
아침에 "오늘 브리핑" 한마디
  → 1층이 전체 포트를 훑고 "AAPL 실적이 3일 남았으니 스토리 리더 돌려봐" 신호

"AAPL 스토리 분석해줘"
  → 2층이 최근 3개년 10-K와 어닝콜을 비교해
    "이번 분기 가이던스 표현이 미묘하게 약해졌다"는 걸 원문 인용과 함께 제시

"AAPL 지금 사도 되나?"
  → 가격 판독기가 "지금 주가가 성립하려면 향후 10년 연 X% 성장이 필요한데,
    지난 5년 실제 성장률은 Y%였다"는 갭을 보여줌

판단은 내가 한다. AI는 여기까지.
```

## 7. 왜 이런 방식으로 만들었나

- **스킬(SKILL.md) 단위로 쪼갠 이유**: 각 분석은 절차와 출력 형식이 반복되기 때문에, 매번 프롬프트를 새로 쓰는 대신 "트리거 문구 + 절대 규칙 + 출력 구성"을 문서 하나에 고정해뒀습니다. 트리거 문구를 던지면 항상 같은 품질의 결과가 나옵니다.
- **계산을 코드 실행에 위임한 이유**: LLM이 암산하면 큰 자릿수에서 실수가 잦습니다. 역DCF의 이분법 계산 같은 건 반드시 코드로 돌리게 강제했습니다.
- **매매 신호를 원천 차단한 이유**: 이 도구가 "사라/팔아라"를 말하기 시작하면, 그 순간부터 책임 소재가 애매해지고 AI 환각의 리스크가 실제 돈 손실로 바로 연결됩니다. 역할을 "리서치 보조"로 딱 자르는 게 오히려 더 안전하고 오래 쓸 수 있는 설계라고 판단했습니다.
- **출처를 URL/페이지로 강제한 이유**: 숫자를 지어내는 게 가장 위험한 실패 모드입니다. "확인 필요"라고 정직하게 말하는 게 그럴듯한 오답보다 훨씬 낫습니다.

## 8. 한계

- 실시간 계좌 연동은 하지 않습니다(자격증명을 다루지 않는 게 안전하다고 판단). 보유 현황은 `data/portfolio.md`에 수동으로 갱신합니다.
- 한국 상장 기업은 어닝콜 전문 공개가 미국만큼 흔치 않아서, 스토리 분석의 정밀도가 상대적으로 낮다는 걸 스스로 알려줍니다.
- 이 시스템이 내리는 어떤 결론도 투자 자문이 아닙니다. 후보를 좁히는 1차 스크리너로만 쓰고, 실제 판단에 쓰는 숫자는 원문에서 재확인하는 걸 원칙으로 하고 있습니다.
