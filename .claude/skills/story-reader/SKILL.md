# 스토리 리더 (Story Reader)

시작하기 전에 `.claude/skills/investing-principles.md`를 반드시 먼저 읽는다.

## 목적
한 시점의 스냅샷이 아니라 **변화의 방향**을 본다. 사람이 수백 페이지짜리 공시 여러 개를 나란히 놓고 비교하는 건 현실적으로 어렵다 — 이걸 대신한다.

## 필요 입력
- 최근 2~3개년 10-K/사업보고서 (업로드 권장). 업로드가 없으면 웹검색으로 확보 가능한 범위까지만 하고, 그 사실을 출력에 명시한다.
- 가능하면 최근 4~8개 분기 어닝콜(실적 발표 콘퍼런스콜) 스크립트나 요약.

## 프로세스
1. **문구 비교(연도별)** — 동일한 섹션(사업 개요, 리스크 요인, 경영진 논의 MD&A)을 연도순으로 나열해 다음을 찾는다.
   - 새로 등장한 문구/섹션
   - 사라진 문구/섹션
   - 미묘하게 약해진 표현 (예: "will" → "may", "강력한 성장" → "안정적 성장", 확정적 어투 → 조건부 어투)

   각 변화는 원문을 그대로 인용하고 페이지 번호를 명시한다. 페이지 번호 추측 금지.
2. **가이던스 vs 실제** — 각 분기/연도에 경영진이 제시한 가이던스(매출, 마진 등 숫자로 된 약속)를 표로 뽑고, 실제 달성치와 대조한다. 달성/미달/초과를 코드로 계산해 표시한다.
3. **어닝콜 톤 추적** — 분기별로 경영진 발언의 자신감 톤을 `[해석]`으로 정성 평가(상승/유지/하락)하되, 반드시 근거가 된 발언을 원문 인용으로 함께 제시한다. 인용 없는 톤 평가는 쓰지 않는다.
4. **변화 없음도 결과다** — 비교했는데 유의미한 변화가 없으면 "변화 없음"이라고 정직하게 쓴다. 억지로 트렌드를 만들어내지 않는다.

## 출력 형식
```
# [기업명] 스토리 리더 — [연도 범위]
생성일: YYYY-MM-DD

## 요약 (3줄 이내)
[해석] ...

## 문구 변화 타임라인
| 연도 | 섹션 | 변화 | 원문 인용 (출처) |
|---|---|---|---|

## 가이던스 vs 실제
| 기간 | 제시한 가이던스 | 실제 | 결과 |
|---|---|---|---|

## 어닝콜 톤 추적
| 분기 | 톤 평가 [해석] | 근거 발언 [사실] (출처) |
|---|---|---|

## 종합 판단
[해석] 스토리가 개선/악화/변화없음 중 무엇인지, 근거와 함께.

## 확인 필요
- ...
```

## 저장
결과물은 `output/cards/[티커]_story_[YYYY-MM-DD].md`로 저장한다.

## 금지사항
- 매수/매도 의견을 내지 않는다. "어디를 더 파봐야 하는지"만 제시한다 (예: "다음 분기 가이던스 재확인 필요").
- 원문 인용 없는 톤 평가를 쓰지 않는다.
- 페이지 번호 추측 금지.
